# ARCHITECTURE 构建指南

本指南定义如何从任意项目上下文构建 ARCHITECTURE 系列文档。

## 输入类型

可接受输入包括：

- PRD、需求规格说明书、产品原型说明
- 现有 README、部署文档、运维文档
- 源码、数据库脚本、配置文件
- OpenAPI、接口文档、Postman 集合
- 测试用例、自动化测试、验收记录
- 会议纪要、问题清单、历史决策

## 构建流程

1. 收集输入
   - 列出所有可用资料。
   - 标记每个资料的可信度、更新时间和覆盖范围。

2. 抽取事实
   - 提取实体、角色、状态、流程、权限、模块、外部依赖。
   - 对源码项目额外提取包结构、表结构、接口路径和服务依赖。

3. 归一化
   - 合并同义术语。
   - 标记冲突表达。
   - 区分稳定架构和易变细节。

4. 建模
   - 形成领域模型、能力模型、状态机、模块边界和不变量。
   - 将通用能力和业务能力分开。

5. 生成文档
   - 输出 `project/ARCHITECTURE.md`。
   - 按模块输出 `project/modules/*.md`。
   - 输出 `glossary.md` 和 `source-map.md`。
   - 对关键取舍输出 ADR。

6. 校验
   - 运行结构和链接检查。
   - 人工审查待确认项、冲突项和不变量。

## 内容分层

顶层文档保留稳定架构，模块文档承载详细规则，PRD 保留产品细节，测试工程文档保留验证方法。

| 内容 | 推荐位置 |
| --- | --- |
| 系统核心实体 | `project/ARCHITECTURE.md` |
| 状态机和不可逆规则 | `project/ARCHITECTURE.md` 或状态机模块 |
| 字段全集 | 模块文档或 PRD |
| 页面布局 | PRD 或交互文档 |
| 接口参数 | 接口文档 |
| 测试执行规范 | 测试工程 |
| 架构取舍 | `project/decisions/` |
