# ARCHITECTURE 系列文档规范

> 本规范定义 `ARCHITECTURE.md` 系列文档是什么、如何分层、如何被人和 AI Agent 使用。它不绑定任何单一业务项目。

## 文档定位

`ARCHITECTURE.md` 系列文档是项目的稳定架构基线，用于把 PRD、源码、接口、数据库、测试资产、会议纪要等上下文编译为可维护的系统理解。

它的目标不是替代 PRD 或接口文档，而是沉淀跨需求版本稳定存在的结构：

- 领域实体与关系
- 核心状态机和业务流
- 通用能力和业务能力
- 模块边界和依赖
- 权限、安全、审计、数据一致性等不变量
- 重要架构决策及其来源

## 规范性语言

本文档及其子规范使用 RFC 2119 风格动词：

| 动词 | 含义 |
| --- | --- |
| MUST | 硬性要求，不接受例外 |
| MUST NOT | 硬性禁止 |
| SHOULD | 强烈建议，偏离时需要记录原因 |
| MAY | 可选行为 |

## 文档层级

ARCHITECTURE 系列 MUST 分为三层：

| 层级 | 作用 |
| --- | --- |
| meta | 定义架构文档体系自身的规范和指导思想 |
| guide | 定义生成、检查、维护架构文档的实践方法 |
| project | 存放具体项目的架构编译产物 |

## 顶层 ARCHITECTURE.md

顶层项目文档 SHOULD 只保留稳定架构基线，避免承载易变字段全集、页面布局、接口参数全集和测试执行细节。

顶层项目文档 SHOULD 包含：

- 文档定位
- 覆盖范围和不覆盖范围
- 核心实体与关系
- 核心业务流或状态机
- 通用能力
- 模块划分
- 系统不变量
- 子文档索引

## 模块文档

每个模块文档 SHOULD 使用统一结构：

- 模块定位与边界
- 对外提供能力
- 对外依赖
- 核心实体
- 功能清单
- 业务规则
- 权限规则
- 状态或流程规则
- 数据一致性要求
- 用户交互流程
- 不实现范围

## 与其他文档的关系

| 文档类型 | 与 ARCHITECTURE 的关系 |
| --- | --- |
| PRD | 输入来源，提供业务目标、范围和需求细节 |
| README | 输入来源，提供工程启动、部署和运行说明 |
| 接口文档 | 输入来源或下游产物，不应替代架构模块边界 |
| 测试工程文档 | 独立体系，可消费架构基线，但不属于业务架构系列 |
| 源码 | 输入来源，也是架构事实校验来源 |
