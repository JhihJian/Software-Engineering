# 不变量规则

不变量是系统在任何实现、重构、需求细化中都必须保持成立的硬约束。

## 不变量判定

满足以下条件之一的规则 SHOULD 进入不变量：

- 违反后会造成安全、权限、审计或数据一致性风险
- 违反后会破坏核心业务流程
- 违反后会导致跨模块契约失效
- 违反后需要数据修复或人工补偿
- 多个模块都依赖该规则

## 不应进入不变量的内容

- 页面字段顺序
- 表格列宽、颜色、布局细节
- 单个接口的临时参数
- 尚未确认的产品想法
- 可以在不影响系统语义的情况下自由调整的实现细节

## 推荐表达方式

每条不变量 SHOULD 包含：

- 规则描述
- 适用范围
- 违反后果
- 主要来源
- 校验方式

示例：

```text
规则：所有业务接口必须从已认证 token 获取用户身份。
范围：所有业务模块。
后果：信任客户端身份头会造成越权。
来源：权限模型、用户权限模块。
校验：代码扫描 + 接口测试。
```
