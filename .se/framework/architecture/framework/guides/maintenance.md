# ARCHITECTURE 维护指南

ARCHITECTURE 系列文档应随系统事实演进，但不应被每个细节需求扰动。

## 何时更新

以下变化 MUST 更新架构文档：

- 新增或删除核心实体
- 核心状态机或业务闭环变化
- 权限、安全、审计、数据一致性规则变化
- 模块边界或依赖关系变化
- 通用能力新增、删除或职责迁移
- 重要架构决策变化

以下变化通常不需要更新顶层架构：

- 页面布局微调
- 文案、颜色、排序等展示细节
- 单个字段的展示规则
- 非核心接口参数调整

## 维护流程

1. 定位变化来源。
2. 判断影响层级：顶层、模块、术语、来源映射或 ADR。
3. 更新最小必要文档。
4. 同步更新索引和 `source-map.md`。
5. 运行 `npm run architecture:check`。
6. 对不确定内容标记为待确认。

## 漂移处理

当 PRD、源码和架构文档冲突时，SHOULD 按以下顺序处理：

1. 识别冲突点。
2. 标记来源和证据。
3. 如果源码代表已上线事实，记录为当前事实。
4. 如果 PRD 代表目标状态，记录为目标约束。
5. 无法判断时标记待确认，不直接覆盖。
